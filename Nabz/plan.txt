NABZ SCRIBE: URDU NOTE-WRITER TEST ON THE RTX A4000 PC
Written 9 November 2026. Claude Code: read all of this, then carry it out from start to finish without asking,
except where a step says STOP. Work inside the Nabz folder (the folder this file is in).

==========================================================================================
WHAT THIS IS FOR
==========================================================================================
The phone app will use Whisper base (Urdu forced) for speech to text. Its transcripts are already in
results/asr/avx2_base-q8_ur_t4/. On those, Qwen 2.5 7B found only 6% of medicines (see results/RUN_NOTES.md).
This test asks one question: do Urdu-trained LLMs write better notes from those transcripts than Qwen?

No audio is needed and no speech recognition is run on this machine. Only the note writer runs, on the GPU.
Do not collect data, fine-tune anything, or change the scoring scripts (score_note.py, drug_check.py, report.py).

Models (all GGUF, Q4_K_M, about 2 to 5 GB each, run with llama.cpp on the GPU):

  tag          repo                                         file
  qwen35-4b    bartowski/Qwen_Qwen3.5-4B-GGUF               Qwen_Qwen3.5-4B-Q4_K_M.gguf          (baseline from the spike)
  alif-8b      large-traversaal/Alif-1.0-8B-Instruct        model-Q4_K_M.gguf                    (Urdu, Llama 3.1 8B)
  alif-3b      large-traversaal/Alif-1.0-3B-Instruct        Alif-1.0-3B-Instruct-Q4_K_M.gguf     (Urdu, small enough for a phone)
  qalb-8b      mradermacher/Qalb-1.0-8B-Instruct-GGUF       Qalb-1.0-8B-Instruct.Q4_K_M.gguf     (Urdu, Llama 3.1 8B)
  shaheen-7b   Khurram123/Qwen-Urdu-Shaheen-7B-Instruct-v1  shaheen_v1_q4_k_m.gguf               (Urdu, Qwen 2.5 7B)

Sources (transcripts each model turns into notes):
  ref                   the Roman Urdu reference text: the model's own errors on clean input
  avx2_base-q8_ur_t4    real Whisper base output: what the app will actually see

Run every model on both sources, except qwen35-4b on ref: results/notes/ref__qwen35-4b/ already exists.
That makes 9 runs of 39 notes each.

==========================================================================================
STEP 3. LLAMA.CPP WITH CUDA (prebuilt, pinned to release b11912 of 26 Oct 2026)
==========================================================================================
Base URL: https://github.com/ggml-org/llama.cpp/releases/download/b11912/

Windows: download both zips and extract both into llama.cpp/build/bin/ (the cudart zip holds the CUDA DLLs):
  llama-b11912-bin-win-cuda-12.4-x64.zip       (about 280 MB)
  cudart-llama-bin-win-cuda-12.4-x64.zip       (about 390 MB)
Linux: download cudart-llama-b11912-bin-ubuntu-cuda-12.8-x64.tar.gz (about 590 MB) and extract it into
  llama.cpp/build/bin/. If llama-server is not in it, also extract llama-b11912-bin-ubuntu-cuda-12.8-x64.tar.gz.

Downloads may drop part way on a weak connection. Use "curl -L -C - --retry 10 -o <file> <url>" in a loop
until the file is full size, and check that the archive opens before extracting.

If an archive puts the files in a subfolder, move them so llama-server(.exe) sits directly in
llama.cpp/build/bin/.

Check: "llama.cpp/build/bin/llama-server --version" runs, and "llama-server --list-devices" shows the A4000.
If the driver is too old for CUDA 12.4 (nvidia-smi says CUDA below 12.4): STOP and tell the user to update the
NVIDIA driver. If no CUDA device is listed after that, as a last resort build from source:
  git clone --depth 1 --branch b11912 https://github.com/ggml-org/llama.cpp llama.cpp/src
  cmake -S llama.cpp/src -B llama.cpp/src/build -DGGML_CUDA=ON
  cmake --build llama.cpp/src/build --config Release -j --target llama-server
and copy the binaries into llama.cpp/build/bin/ (this needs the CUDA toolkit installed).

==========================================================================================
STEP 5. WRITE THE NOTES
==========================================================================================
For each model, in table order:

  a. Start the server in the background and keep its log:
       llama.cpp/build/bin/llama-server -m models/<file> -ngl 99 -c 4096 --jinja --port 8080
     (Log to a file, e.g. llama-<tag>.log. .log files are git-ignored.)
  b. Wait until http://127.0.0.1:8080/v1/models answers (up to 3 minutes).
  c. Run (skip the ref line for qwen35-4b):
       python run_note.py --source ref                --model-tag <tag> --timeout 300
       python run_note.py --source avx2_base-q8_ur_t4 --model-tag <tag> --timeout 300
  d. Stop the server and make sure port 8080 is free before the next model.

Checks after each run:
  - results/notes/<source>__<tag>/ should hold 39 .json files. If some are missing, rerun the same command:
    it skips notes already written.
  - Most lines should say "ok". If the server returns errors on every note (for example, a chat-template error),
    try the server once without --jinja. If it still fails, record the error for that model in step 7 and move on.
    Do not edit run_note.py or the prompt to make one model look better: every model gets the same prompt.
  - A model that writes nonsense or invalid JSON is a result, not a failure. Keep it.

Every note on the GPU should take a few seconds, so all 9 runs should take well under an hour.
